# 技术适配声明

> Kids Mind 育儿多智能体 V1.0 | 阶段 1 技术适配 | 2026-09-16

## 1. 产品形态判断
- **产品类型与核心任务**：0-3 岁新手父母的育儿助手。四大能力：①育儿问答（可信、带引用、风险分级 L1-L4）②成长档案（儿童档案 + 记录 + 时间线）③提醒 ④数字绘本（个性化故事 + 插画 + 朗读 + 书架）。
- **核心交互**：混合型——问答 = 多轮对话（最多追问 2 轮）；故事 = 分阶段确认（确认大纲与插画风格后生成）；成长记录 = 表单录入（≤3 步）。
- **开发路径**：**后端先行**。核心价值在"问答可信度 + 风险分级"和"故事生成质量"，这些必须先靠 API + 最小验收界面验证 Agent 效果，再投入正式前端。
- **当前阶段范围**：阶段 2 后端 MVP，分 3 个子阶段——第 1 阶段：儿童档案 + 育儿问答（RAG 引用 + 风险分级 + 追问）；第 2 阶段：成长记录 + 提醒 + 时间线；第 3 阶段：故事工坊（大纲/正文/插画/朗读/书架）。

## 2. 采用的默认方案
| 方案 | 采用原因 |
| --- | --- |
| Python 3.12 + FastAPI | 默认后端基线，能力可做成可测试的 API |
| Pydantic + pytest | 接口与模型结构化输出校验 + 自动化测试 |
| Git | 强制底线，保存变更可恢复 |
| DeepSeek deepseek-flash（OpenAI 兼容接口） | 问答文本模型，已联网核实为便宜款，满足合规与成本上限 |

## 4. 偏离或暂缓的默认方案
| 默认方案 | 替代/暂缓 | 原因 | 影响 | 未来何时重评 |
| --- | --- | --- | --- | --- |
| 终端按 PRD = 移动端 App（React Native） | MVP 阶段先用**响应式 Web 最小验收界面**（手机浏览器可开），正式 App 在阶段 3 用 React Native 做 | 核心价值先用网页验证，避免效果未定时投入重资源做原生 App | 交付终端顺序变化（见下方待确认） | 阶段 3 正式前端 |

| 数据库 SQLite | MVP 用 SQLite（10 人够用） | 内部试用规模小 | 阶段 4 上线前评估云数据库/PostgreSQL | 阶段 4 |
| 对象存储 | MVP 本地文件目录 | 试用期文件量小 | 阶段 4 上线换云对象存储 | 阶段 4 |

## 5. 强制底线检查
- **密钥与隐私**：通过。DeepSeek 等 Key 放项目内已加入 `.gitignore` 的 `.env`，不进仓库/前端/日志/对话；儿童数据按敏感数据处理。
- **数据与任务可恢复**：通过。档案、记录、提醒、任务全部落 SQLite 持久化，重启可恢复。
- **输入输出校验**：通过。Pydantic 校验接口，模型输出结构校验（JSON 输出 + 失败重试）。
- **错误与日志边界**：通过。统一 `{"error":{"code","message"}}`，不泄露堆栈；SSE 以 `done`/`error` 收尾；L1/L2 危急内容生成前后双审。
- **测试与真实模型验收**：计划 = 每个子阶段先 mock 自动化测试，再用真实 DeepSeek 冒烟；问答与故事用 5-10 条真实样例打分定 D2 基线。

## 7. 需要产品经理决定的问题
### 问题 1：MVP 试用阶段的产品形态（交付终端顺序）
- 为什么重要：PRD 写"移动端 App 为主阵地"，但 MVP 是 10 人内部试用，先做原生 App 周期长、改版贵。
- 选项：A. 先做**响应式网页**（手机浏览器直接打开用，做了手机适配），验证核心能力，正式 App 在阶段 3 用 React Native 做；B. 直接做**原生手机 App**。
- 推荐：**A**。核心价值（问答可信度、故事质量）先用网页验证，10 人内部试用体验够用；验证通过后再做 App，避免效果未定就投入重资源。
- 不选的后果：选 B 会显著拉长开发周期、改版返工成本高。
