# 第 2 阶段技术开发文档｜成长记录 + 提醒 + 时间线（后端 MVP）

> 配套文档：Kids Mind 育儿多智能体 PRD V1.0、《技术适配声明》、第 1 阶段技术开发文档。
> 本文档只覆盖阶段 2 后端 MVP 第 2 阶段，不提前实现故事工坊、语音输入、正式 App、推送。

## 一、阶段目标
- **交付范围**（对齐 PRD FR-02/FR-03/FR-04 + M1 闭环原型）：
  1. 事件记录：喂养、睡眠、排便、身高体重、里程碑、自定义六类；录入 ≤3 步；可修改、删除。
  2. 提醒：疫苗、喂养、作息、自定义四类；可增删改查；支持"即将到期"列表。
  3. 时间线：按日期倒序展示事件，支持按类型/日期筛选。
- **阶段产物**：backend 新增 Event/Reminder 模型 + 接口 + 最小验收界面扩展；mock 测试。
- **验收标准**：记录/提醒/时间线全链路可用；数据重启可恢复；mock 测试全绿。
- **明确不做**：真实推送通知（需 App/授权，属阶段 3/4）、故事工坊（第 3 阶段）、语音输入。
- **本阶段主链路片段**：建档案 → 录一条喂养/睡眠记录 → 时间线按日期看到 → 建一条提醒 → 提醒列表可见。

## 二、技术适配摘要
- 开发路径：后端先行；本阶段为纯 CRUD 工程阶段，**不调用模型**。
- 采用默认：FastAPI + SQLAlchemy(SQLite) + Pydantic + pytest。
- 偏离/暂缓：真实推送通知暂缓（本阶段只做提醒数据与列表，推送等 App 端通知授权后再做）。

## 三、技术栈与模型
- 组件：同第 1 阶段（FastAPI/SQLAlchemy/Pydantic/pytest），无新增依赖，无模型调用。

## 四、环境与配置
- 同第 1 阶段；启动端口仍为 8001（8000 被其他项目占用）。

## 六、数据、资产与状态
- 表 `events`：id、child_id(FK)、type(枚举：feeding/sleep/diaper/growth/milestone/custom)、title、note、occurred_at(事件发生时间)、data_json(结构化字段，如喂养量/睡眠时长/身高体重)、created_at、updated_at。
- 表 `reminders`：id、child_id(FK)、type(枚举：vaccine/feeding/routine/custom)、title、note、remind_at、repeat(one/interval，MVP 先 one)、enabled(默认 true)、notified_at(可空)、created_at。
- 状态机：提醒 `enabled` 布尔 + `notified_at` 标记；本阶段不做自动触发，仅数据与列表。
- 资产：无。

## 七、API / 工具设计
统一错误 `{"error":{"code","message"}}`。

事件：
- `POST /api/v1/children/{child_id}/events`：请求 `{type, title?, note?, occurred_at, data?}`；响应 201。
- `GET /api/v1/children/{child_id}/events?type=&from=&to=`：响应 `{items:[...]}`。
- `PUT /api/v1/events/{id}`：部分更新；`DELETE /api/v1/events/{id}`：删除（软删字段 deleted_at）。
- `GET /api/v1/children/{child_id}/timeline?type=`：按日期倒序分组返回 `{groups:[{date, items:[...]}]}`。

提醒：
- `POST /api/v1/children/{child_id}/reminders`、`GET .../reminders?enabled=`、`PUT /api/v1/reminders/{id}`、`DELETE /api/v1/reminders/{id}`。
- `GET /api/v1/children/{child_id}/reminders/upcoming?days=7`：未来 N 天到期提醒。

校验：type 必须在枚举内；occurred_at/remind_at 合法时间；child_id 存在。

## 十、测试要求
- 第一层 mock（pytest，无模型）：
  1. 事件：创建（各类型）、列表筛选（type/日期）、更新、删除（软删后列表不含）。
  2. 时间线：按日期倒序分组、类型筛选。
  3. 提醒：创建、列表、更新 enabled、删除、upcoming 按天数过滤。
  4. 校验：非法 type、非法日期、child 不存在 → 统一错误结构。
- 第二层真实冒烟：**N/A**（本阶段无模型调用，说明覆盖关系）。

## 十一、验收清单（产品经理照着点）
1. 打开 http://localhost:8001，选中已有儿童。
2. 在"③ 成长记录"选"喂养"，填内容保存 → 时间线出现这条。
3. 再录一条"睡眠"，看时间线按日期倒序、可筛选。
4. 修改一条记录、删除一条记录，列表/时间线同步变化。
5. 在"⑤ 提醒"新增一条疫苗提醒（选未来日期）→ 列表出现；删掉后消失。
6. 重启服务后（我操作）数据仍在。
