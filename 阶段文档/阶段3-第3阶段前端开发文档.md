# 阶段 3 第 3 阶段前端开发文档

> Kids Mind 正式前端·成长页（记录 + 时间线 + 提醒） | 2026-09-18

## 1. 本阶段目标
家长在「成长」页选中孩子后，可以按日期回看成长时间线，用六类事件记录喂养/睡眠/排便/身高体重/里程碑/自定义，并管理疫苗、喂养、作息、自定义四类提醒（增删改、启用/停用）。

## 2. 范围

### 包含
- `/growth` 成长页（替换占位页）：孩子选择器、时间线 / 提醒两个标签页。
- 时间线：按日期倒序分组展示六类事件，类型筛选（全部/喂养/睡眠/排便/身高体重/里程碑/自定义）。
- 记录：六类事件的新增、编辑、软删除；类型化表单（喂养-奶量、睡眠-时长、排便-性状、身高体重-数值、里程碑/自定义-标题）。
- 提醒：四类提醒的新增、编辑、删除、启用/停用开关。
- 快捷记录：支持 `/growth?type=feeding|sleep|growth|milestone` 直达对应记录表单（配合首页快捷记录卡片）。
- 无档案空状态、加载、失败重试、空数据状态。

### 不包含
- 儿童档案编辑（后端无更新/删除接口，阶段 4 补后端后接入）。
- 真实推送通知（需 App 通知授权，阶段 3/4 暂缓）。
- 成长曲线图表（身高体重趋势，后续子阶段）。
- 故事、我的页面（后续子阶段）。

## 3. 用户流程
1. 打开成长页，读取儿童列表；无档案引导建档。
2. 默认进入「时间线」，按日期看到历史记录；顶部筛选类型。
3. 点「记一笔」选类型填内容保存，时间线立即出现。
4. 点记录右侧铅笔编辑、垃圾桶删除（二次确认）。
5. 切到「提醒」，看到全部提醒；添加/编辑/删除，开关启用停用。

## 5. 接口契约
- `GET /api/v1/children/{id}/timeline?type=`：按日期分组的时间线。
- `POST /api/v1/children/{id}/events` / `PUT /api/v1/events/{id}` / `DELETE /api/v1/events/{id}`：记录增改删。
- `GET /api/v1/children/{id}/reminders` / `POST /api/v1/children/{id}/reminders` / `PUT /api/v1/reminders/{id}` / `DELETE /api/v1/reminders/{id}`：提醒增删改查。
- 提醒更新为部分更新（title/note/remind_at/enabled），类型与重复频率后端不支持修改，编辑弹窗中类型只读。
- 所有请求经 `lib/api.ts` 统一处理；`DELETE` 返回 204 无 body，单独用 `apiDelete` 处理。

## 6. 实现方案
- 组件：`GrowthPage`（页面编排）→ `EventDialog`（六类记录表单）、`ReminderDialog`（提醒表单）。
- 数据：后端是事实来源；本机 child 偏好沿用 Local Storage；时间线全量加载后前端按类型筛选，切换筛选不重新请求。
- 表单：记录 `data` 存结构化字段（feeding.amount / sleep.duration / diaper.kind / growth.height+weight），里程碑与自定义存 title；`format.ts` 提供 `eventDetail` 统一渲染摘要。
- 安全：删除为不可逆软删，前端 `window.confirm` 二次确认；无任何密钥。
- 响应式：390px 单列、筛选条横向滚动；768px 起正常两栏；沿用 AppShell 桌面侧栏 + 移动底部导航。

- 真实闭环：建档案 → 记一笔喂养 → 时间线按日期出现 → 编辑/删除同步 → 添加提醒 → 开关停用。

## 8. 风险与回退
- 风险：儿童档案无更新接口，本阶段只读展示、建档走 ChildDialog。处理：阶段 4 补后端后接入档案编辑。
- 风险：`window.confirm` 在无头浏览器不可见，仅用于二次确认，不影响功能。
- 回退：本阶段新增均为叠加，不改动首页、问育儿、故事、我的路由与后端既有接口。
