# 阶段 3 第 2 阶段前端开发文档

> Kids Mind 正式前端·问育儿第一条真实闭环 | 2026-09-18

## 1. 本阶段目标
家长选中一个孩子后，在「问育儿」页输入育儿问题，看到一条基于真实后端的流式 CARE 答案（结论 / 可以这么做 / 依据 / 就医信号 / 免责声明），并带风险分级徽标与来源引用；刷新或重进后能从会话历史恢复。危急提问（L1/L2）立即中断并先出急救/就医提示，不调用模型。

## 2. 范围

### 包含
- `/ask` 问育儿页（替换占位页）：孩子选择器、会话列表、消息流、提问输入。
- SSE 流式问答（POST /api/v1/qa 的 chunk / done / error 事件），用 Fetch Streaming 解析。
- CARE 结构化答案展示：结论、可以这么做、依据、出现这些情况请就医、免责声明。
- 风险分级徽标：L1 危急 / L2 紧急 / L3 观察 / L4 常规 / 需要补充信息。
- 来源引用（标题、来源、版本、审核状态）。
- 多轮对话：同一会话内追问，后端最多追问 2 轮；展示追问问句作为引导。
- 会话历史：后端新增会话列表接口，前端可切换历史会话、刷新后恢复。
- 无档案空状态（引导建档，复用 ChildDialog）、加载、失败、流式中、断线重试状态。

### 不包含
- 语音输入（后端 ASR 未做，阶段 3 暂缓项）。
- 答案反馈（点赞/点踩）、专家/分诊/医院导航入口（FR-13 连续 3 轮未解决的兜底，后续子阶段）。
- 邀请码登录（后端无会话能力，不做前端假登录）。
- 成长、故事、我的页面（后续子阶段分别铺开）。

## 3. 用户流程
1. 打开问育儿页，读取儿童列表；无档案引导建档。
2. 选中孩子后加载该孩子的历史会话；无历史时显示"开始提问"空状态。
3. 输入问题提交，消息流立即出现用户气泡，助手气泡进入"正在组织回答"流式状态。
4. 答案文本逐段出现；L1/L2 立即显示急救/就医提示；L3/L4/常规显示 CARE 结构 + 来源 + 风险徽标。
5. 后端要求补充信息时，展示追问问句，用户继续输入走同一会话。
6. 刷新页面后，按会话 ID 恢复历史消息；切换孩子后加载对应会话。

## 4. 页面状态矩阵
| 页面/模块 | 初始/加载 | 空 | 成功 | 失败 | 恢复 |
| --- | --- | --- | --- | --- | --- |
| 问育儿页 | "正在读取孩子档案…" | 无档案引导建档；有档案无会话显示"开始提问" | 展示会话列表 + 消息流 | 后端断开说明并允许重试 | 按会话 ID 重拉历史 |

## 5. 接口契约
- `POST /api/v1/qa`：body `{child_id, question, conversation_id?}`；SSE 返回 `chunk`（增量文本）、`done`（完整结构化结果，含 conversation_id/risk_level/conclusion/actions/evidence/red_flags/disclaimer/followup_question/followup_count/sources）、`error`（`{"error":{"code","message"}}`）。
- `GET /api/v1/qa/conversations?child_id={id}`：**本阶段后端新增**，返回 `{items:[{id, child_id, title, created_at, updated_at}]}`，`title` 取该会话首条用户消息前 24 字。
- `GET /api/v1/qa/conversations/{id}`：返回会话历史 `{conversation_id, child_id, messages:[{role, content, risk_level, sources, created_at}]}`。
- 所有请求经 `lib/api.ts` 统一处理；流式请求单独 60 秒超时；前端不含任何密钥。

## 6. 实现方案
- 路由：`/ask` 客户端组件，保留 AppShell 桌面侧栏 + 移动底部导航。
- 组件：`AskPage`（页面编排）→ `ConversationList`（会话侧栏）、`MessageList`（消息流）、`AnswerCard`（CARE 结构）、`RiskBadge`（分级徽标）、`SourceList`（来源引用）、`QuestionComposer`（输入提交）。
- 流式：`fetch` + `ReadableStream` 逐行解析 SSE；`chunk` 追加文本，`done` 以结构化结果为准重建完整答案（后端已返回完整 answer，避免 chunk 拼接误差），`error` 停止并显示安全错误。
- 状态：后端是事实来源；当前 child id 与当前会话 id 存 URL query（`/ask?child=&conv=`），刷新可恢复；本机 child 偏好沿用首页的 Local Storage。
- 安全：仅展示 `sources` 白名单字段与 `disclaimer`；不渲染模型原始 JSON；L1/L2 确定性话术直接来自后端。
- 响应式：390px 单列（会话列表折叠为下拉/抽屉），768px 起双栏（会话列表 + 消息流）。

## 7. 验收标准
- `npm run lint`、`npm run typecheck`、`npm run test`、`npm run build` 全部通过。
- 后端 mock 回归测试通过（新增会话列表接口用例）。
- 真实闭环：建档案 → 问"8 个月辅食加什么" → 看到流式 CARE 答案 + 来源；问"宝宝突然抽搐怎么办" → 立即 L1 急救提示（不调模型）；刷新后历史仍在。
- 390 / 768 / 1280 / 1440px 检查，无横向滚动，输入框与提交按钮可触达。
- 断线/后端关闭时显示可重试文案，不丢用户已发送的提问。

## 8. 风险与回退
- 风险：SSE 经 Next.js 同源代理可能被缓冲。处理：真实预览验证逐段到达；若被缓冲，改用直连后端或调整代理。
- 风险：会话列表接口为新增，需保持与现有 `/conversations/{id}` 路径不冲突。处理：精确路径 `/conversations` 与参数路径 `/conversations/{id}` 天然不冲突，加测试覆盖。
- 回退：本阶段不改动既有首页、成长、故事、我的路由与后端既有接口；新增均为叠加。
