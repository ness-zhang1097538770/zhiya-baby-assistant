# 第 1 阶段技术开发文档｜儿童档案 + 育儿问答（后端 MVP）

> 配套文档：Kids Mind 育儿多智能体 PRD V1.0、《技术适配声明》、《AI Agent 产品 Vibe Coding 通用技术栈手册》。
> 本文档只覆盖阶段 2 后端 MVP 第 1 阶段，不提前实现记录/提醒/故事工坊。

## 一、阶段目标
- **交付范围**（对齐 PRD M1 闭环原型 + FR-01/FR-10~13）：
  1. 儿童档案：创建 / 列表 / 编辑（昵称、出生日期必填；性别、喂养方式、过敏史、早产史可选）。
  2. 育儿问答：文本提问 → 风险分级（L1-L4）→ L1/L2 走确定性急救/强就医提示（不调模型），L3/L4 走 RAG + DeepSeek 生成 CARE 结构化答案 → SSE 流式返回（chunk → done/error）。
  3. 会话历史与最多 2 轮追问。
- **阶段产物**：backend（FastAPI + SQLite + SSE + RAG 关键词检索 + 最小验收界面 static/index.html）、mock 测试、真实模型冒烟记录。
- **验收标准**：建档/问答全链路可用；L1/L2 秒回且内容为确定性安全话术；L3/L4 返回 CARE 五要素并带来源与免责声明；mock 测试全绿；真实 DeepSeek 冒烟跑通 5 条样例（D2 待样例打分）。
- **明确不做**：成长记录/提醒/时间线（第 2 阶段）、故事工坊（第 3 阶段）、语音输入、正式 App、登录/邀请码。
- **本阶段主链路片段**：建档 → 提问 → 风险分级 → （L4）RAG 检索 → 生成 CARE → SSE 返回 → 可查看会话历史。

## 二、技术适配摘要
- 引用《技术适配声明》结论；开发路径：**后端先行**。
- 采用默认：Python 3.12 + FastAPI + Pydantic + pytest + Git；DeepSeek deepseek-flash（OpenAI 兼容接口）。
- 启用按需模块：SQLite + SQLAlchemy（档案/会话/消息/知识库多实体）；SSE（问答流式）；本地文件目录暂不需要（本阶段无图片/音频）。
- 偏离/暂缓：**RAG 暂用 SQLite + 关键词检索，暂缓 Chroma**（MVP 知识条目少，可全文直接搜索；条目规模化后引入向量检索）。语音输入暂缓（先文本）。

## 三、技术栈与模型
- 组件：FastAPI、SQLAlchemy（SQLite）、Pydantic、httpx/openai、uvicorn、pytest、python-dotenv。
- 模型：DeepSeek deepseek-flash（`DEEPSEEK_MODEL=deepseek-flash`，`DEEPSEEK_BASE_URL=https://api.deepseek.com`）。
- 不引入：Chroma、python-docx、任务队列（本阶段无此需求）。

## 四、环境与配置
- 配置项（`.env.example`，不含秘密）：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DEEPSEEK_TIMEOUT`、`DB_PATH`。
- 用户提供：DeepSeek API Key（开发期可缺省，验收前必填）。
- 启动：`uvicorn app.main:app --reload --port 8000`；端口冲突时用 `--port 8001` 并记录。

## 六、数据、资产与状态
- 持久化：SQLite（`data/app.db`），SQLAlchemy ORM；重启可恢复。
- 表：
  - `children`：id、nickname、birth_date、gender、feeding_method、allergy_history、premature、created_at、updated_at。
  - `conversations`：id、child_id、created_at、updated_at。
  - `messages`：id、conversation_id、role（user/assistant）、content、risk_level、sources_json、followup_count、created_at。
  - `knowledge_entries`：id、title、category、applicable_age、content、source、version、evidence_level、review_status、tags、created_at。
- 状态机（本阶段）：会话无显式状态枚举，靠 `followup_count` 计数追问轮次（上限 2，确定性代码约束）。
- 资产：本阶段无图片/音频。

## 七、API / 工具设计
统一错误：`{"error": {"code", "message"}}`，不泄露堆栈。

- `POST /api/v1/children`：请求 `{nickname, birth_date, gender?, feeding_method?, allergy_history?, premature?}`；响应 201 `{id, ...}`。校验：nickname 非空、birth_date 合法日期。
- `GET /api/v1/children`：响应 `{items: [...]}`。
- `POST /api/v1/qa`：请求 `{child_id, question, conversation_id?}`；SSE 响应。事件序列：`chunk`（答案文本，0..n 次）→ `done`（完整结构化结果）或 `error`。
  - `done` 数据结构：`{conversation_id, risk_level, answer, conclusion, actions, evidence, red_flags, sources, disclaimer, followup_question, followup_count}`。
  - L1/L2：确定性话术，直接 `done`（无 chunk）；L3/L4：RAG + 模型生成，`chunk` + `done`。
  - 追问：模型返回 `followup_question` 时计入 `followup_count`，≥2 轮后强制给结论。
- `GET /api/v1/qa/conversations/{id}`：响应 `{messages: [...]}`（会话历史）。

SSE 约定：`chunk` 事件 data 为文本片段；`done`/`error` 事件 data 为 JSON；中途失败发 `error` 事件（统一错误结构），不静默断流。SDK 初始化失败（如无 Key）在最外层兜底为 `error` 事件。

## 八、Prompt 设计
`qa_prompt.py` 输出 `build_qa_prompt()`，输入变量：child_context（月龄/喂养/过敏）、question、knowledge（检索到的知识条目，L4 必带）、history（前几轮）。输出要求：严格 JSON（`response_format=json_object`），字段见 §七 done；约束：只依据提供的知识回答、不编造、不诊断不处方、缺关键信息时 `followup_question` 追问（≤2 轮）、必须给出免责声明。Prompt 含正反例（用 `risk_level` 等固定键名，禁止自由发挥格式）。解析器宽容 + Pydantic 强校验，失败有限重试。

## 九、验收界面（按需）
- 需要：问答产出需"用眼睛看、亲手操作"才能判断质量（CARE 是否可执行、来源是否靠谱）。
- 实现：`static/index.html` 单文件（原生 JS + fetch + EventSource 读 SSE），含建档表单 + 问答聊天框。临时验收工具，非正式产品切片。

## 十、测试要求
- 第一层 mock（pytest，模型调用一律 mock）：
  1. 风险分级：L1/L2 关键词命中、L3/L4 默认、优先级 L1>L2。
  2. 档案：创建/列表/校验失败（缺昵称、坏日期）。
  3. 问答：L1 直接 done 且不调模型；L4 mock 模型返回 JSON 正确解析为 done；追问计数上限 2。
  4. 错误路径：无 Key 时 SSE 收 `error` 事件（统一结构）；模型返回坏 JSON 重试后仍失败 → `error`。
  5. 解析器：正反例单测（宽容解析）。
- 第二层真实冒烟（验收前，用真实 Key）：`curl -N` 调 SSE，计时；跑 5 条真实样例（L1 1 条、L4 4 条）记录耗时与成本，交产品经理打样定 D2。
- 数据恢复：重启后会话/消息仍在。

## 十一、验收清单（产品经理照着点）
1. 启动后端（我给出命令），浏览器打开 `http://localhost:8000`。
2. 建档：填昵称 + 出生日期 → 看到档案出现在列表。
3. 问一个常规问题（如"8 个月宝宝辅食可以加什么"）→ 看到答案逐字出现，含结论/行动/依据/就医信号/来源/免责声明。
4. 问一个危急问题（如"宝宝突然抽搐怎么办"）→ 立即看到急救提示 + 120/急诊导航（不等模型）。
5. 问一个需要补充信息的问题 → 系统追问，最多 2 轮。
6. 打开会话历史，能看到刚才的问答。
7. 我逐条展示 5 条真实样例结果，你打分并标出"不能接受"的。

## 十二、风险与待确认项
- 知识库内容为 **MVP 占位知识（来源为公开官方指南摘要，标注"待医学审核"）**，仅用于链路验证；正式上线前需医学团队审核替换。→ 已知限制，不影响本阶段验收。
- 风险分级为关键词规则 + 模型复核，非医疗诊断；免责声明已强制。
- 真实冒烟前需产品经理在 `.env` 填 DeepSeek Key；无 Key 时冒烟"待验"。
- 必须产品经理决定：无（D2 待样例打分在冒烟时执行）。
