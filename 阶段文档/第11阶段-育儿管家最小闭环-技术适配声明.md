# 第 11 阶段：育儿管家最小闭环 — 技术适配声明

> 阶段：3 正式前端（第 11 阶段）· 最近更新：2026-09-27
> 参考：learn-claude-code 的 Agent Harness 工程（s01 Agent Loop / s02 Tool Use / s03 Permission / s09 Memory）

## 1. 本阶段目标

把「一句话入口」从**只分类 + 跳转**升级为**分类 + 直接执行 + 记忆抽取**的最小闭环。
用户一句话可以同时完成多个动作（记录事件 + 创建提醒 + 记住事实），危险 / 花钱的动作走人工确认。

一句话总结（Harness 视角）：给模型「工具 + 权限 + 记忆」，让入口从「路由」变成「动手」。

## 2. 采用的 harness 机制（对应 learn-claude-code 课程）

| 机制 | 课程 | 落地方式 |
| --- | --- | --- |
| Agent Loop | s01 | 模型一次规划（plan），确定性代码执行，结果回填；MVP 为**单轮**，循环结构预留（多轮查询-再作答留待后续） |
| Tool Use | s02 | `TOOL_HANDLERS` 分发表：每个工具一个 handler + schema，新工具只注册不进主循环 |
| Permission | s03 | 每个工具标注 `auto` / `confirm`；确认类动作不直接执行，返回 `pending` 交前端确认 |
| Memory | s09 | 从对话抽取结构化事实，写入新增的 `ChildFact` 记忆表，打 `ai_extract` 标记，可改可删 |

## 3. 架构流程

```
用户一句话
   │
   ▼
LLM 规划（DeepSeek deepseek-flash，chat_json）
   输出 JSON：{intent, reply, actions[{tool, params}]}
   │
   ▼
确定性执行器（白名单校验 + 参数结构校验 + 权限判断）
   ├─ auto 工具 → 直接执行 → executed[]
   ├─ confirm 工具 → 不执行 → pending[]
   └─ 未知/非法工具 → 丢弃，不执行
   │
   ▼
返回 {intent, reply, params, executed[], pending[]}
```

关键点：**模型只做「理解和规划」，执行全部由确定性代码完成**，符合 AGENTS.md 底线第 5 条（高风险/不可逆动作由确定性代码和人工确认约束，不交给模型自主决定）。

## 4. 工具清单与权限

| 工具 | 作用 | 权限 | 说明 |
| --- | --- | --- | --- |
| `record_event` | 记录成长事件（喂养/睡眠/排便/成长/里程碑/其他） | auto | 可撤销，低风险 |
| `create_reminder` | 创建提醒（喂奶/疫苗/作息/其他） | auto | 可撤销，低风险 |
| `save_fact` | 记住事实（过敏/偏好/里程碑/健康/习惯） | auto（默认） | 打 `ai_extract` 标记，可改可删（决策卡 Q1） |
| `create_story` | 发起绘本故事 | confirm | 有模型费用，返回待确认（对应决策 D8） |

## 5. 数据模型（新增）

```python
class ChildFact(Base):
    __tablename__ = "child_facts"
    id / child_id / category / key / value / source / deleted_at / created_at / updated_at
```

- `category`：allergy（过敏）/ preference（偏好）/ milestone（里程碑）/ medical（健康）/ habit（习惯）/ note（备注）
- `source`：ai_extract（AI 抽取）/ manual（手动），用于区分与撤销
- 复用 `get_owned_child` 鉴权，仅本家庭可读写

## 6. 接口

**POST /api/v1/agent/run**

请求：
```json
{"child_id": 1, "text": "宝宝喝了150ml奶，记一下，再定个2小时后喂奶提醒"}
```

响应：
```json
{
  "intent": "action",
  "reply": "已帮你记好，2 小时后提醒你喂奶。",
  "params": {},
  "executed": [
    {"tool": "record_event", "summary": "已记录喂养：喝了150ml奶"},
    {"tool": "create_reminder", "summary": "已创建提醒：2 小时后喂奶"}
  ],
  "pending": []
}
```

错误统一 `{"error": {"code", "message"}}`；LLM 失败兜底 `intent=unknown`，不阻塞入口。

## 7. 模型与成本

- 复用 `llm.chat_json`（DeepSeek deepseek-flash），单次规划调用，**不新增成本项**，仍在 D4 的 150 元/月上限内。

## 8. 安全与底线（对应 AGENTS.md 底线）

1. 白名单校验：任何 action 必须命中 `TOOL_HANDLERS`，未知 tool 一律丢弃。
2. 参数结构校验：非法字段降级/丢弃，不执行。
3. `create_story` 走 confirm（涉及费用）；删除/分享类动作本阶段不开放给模型。
4. 权限判断在后端（`get_owned_child`），前端仅展示，不做权限。
5. 记忆表数据仅本家庭可见；日志不记密钥、不记完整用户文档。

## 9. 验收标准

- mock 测试通过（新增 `tests/test_agent.py`，覆盖：计划归一化、记录/提醒/记忆执行、create_story 待确认、未知工具丢弃、LLM 失败兜底）。
- 真实冒烟：①一句话多动作（记录+提醒）跑通；②含过敏的话 → 记忆抽取写入 ChildFact。
- 前端 IntentBar 内联展示执行结果（本阶段第二子步骤，见阶段文档）。

## 10. 待确认问题（2 个，见项目状态.md「待确认问题」）

- Q1 记忆抽取写入方式：自动写入（带 ai_extract 标记可撤销）vs 每次先确认 —— 推荐自动写入。
- Q2 一句话入口职责边界：动作类内联完成、问答/故事仍跳现有页 vs 全部内联 —— 推荐前者。
