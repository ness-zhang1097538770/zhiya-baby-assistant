# 第 3 阶段技术开发文档｜故事工坊（后端 MVP）

> 配套文档：Kids Mind 育儿多智能体 PRD V1.0（第 6 节故事工坊、第 7 节多智能体）、《技术适配声明》、前序阶段文档。
> 本文档只覆盖阶段 2 后端 MVP 第 3 阶段；插画/朗读的外部服务在子阶段 3-B 单独处理。

## 一、阶段目标
- **交付范围**（对齐 PRD 第 6 节功能流程）：
  1. 故事大纲：输入儿童昵称/年龄/主题/时长/教育目标/家庭记忆 → DeepSeek 生成 8-12 页大纲 → 用户确认（可编辑后确认）。
  2. 故事正文：确认大纲后逐页生成正文 + 朗读文本 + 每页插画提示词（供后续文生图用）。
  3. 书架：故事列表、查看、删除、关联成长时间线。
- **子阶段划分**：3-A 文本核心（本阶段，大纲+正文+书架，仅用 DeepSeek）；3-B 插画+朗读（需文生图/TTS 外部服务 Key，单独核实后做）。
- **验收标准**：新建故事 → 出大纲 → 确认 → 出 8-12 页正文 → 书架可见；mock 测试全绿；真实冒烟跑通 1 个故事（D2 故事维度样例打分）。
- **明确不做**：照片上传/人脸检查、插画/朗读（3-B）、分享、会员/付费。

## 二、技术适配摘要
- 开发路径：后端先行；本阶段为"分阶段确认 + 长耗时生成"，采用 **提交任务 + 轮询状态** 的异步接口（持久化任务状态，重启可恢复）。
- 采用默认：FastAPI + SQLAlchemy + Pydantic + pytest；DeepSeek deepseek-flash。
- 启用按需模块：持久化任务状态（Story.status 字段即任务状态）；本地文件目录（3-B 插画/音频）。
- 偏离/暂缓：插画文生图、朗读 TTS 暂缓到 3-B（外部服务选型与费用待核实）。

## 三、技术栈与模型
- 组件：同前序阶段，无新增依赖。
- 模型：DeepSeek deepseek-flash（大纲 + 正文 + 朗读文本 + 插画提示词均用文本生成）。

## 四、环境与配置
- 同前序阶段；端口 8001。

## 六、数据、资产与状态
- 表 `stories`：id、child_id(FK)、title、character_name、character_tags、theme、age_range、duration、education_goal、family_memory、status、outline_json、pages_json、error、created_at、updated_at。
- **状态机**（持久化，重启可恢复）：
  - `outline_generating` → `outline_ready`（大纲已出，等确认）
  - `outline_ready` → `content_generating`（用户确认后）
  - `content_generating` → `content_ready`（正文已出）
  - 任一生成失败 → `failed`（记录 error，可重试）
- 资产：3-B 阶段插画图片/音频存本地文件目录，元数据存 stories。

## 七、API / 工具设计
统一错误 `{"error":{"code","message"}}`。

- `POST /api/v1/children/{child_id}/stories`：请求 `{character_name, character_tags?, theme, age_range, duration?, education_goal?, family_memory?}`；创建 story（status=outline_generating）并**后台生成大纲**；响应 201 `{id, status}`。
- `GET /api/v1/stories/{id}`：返回 `{id, status, title?, outline?, pages?, error?}`（前端轮询）。
- `POST /api/v1/stories/{id}/confirm`：请求 `{outline?}`（可带编辑后的大纲）；status=content_generating，**后台生成正文**；响应 `{id, status}`。
- `GET /api/v1/children/{child_id}/stories`：书架列表。
- `DELETE /api/v1/stories/{id}`：删除（软删）。

后台生成用 FastAPI BackgroundTasks（每次任务自开 DB 会话）；失败写入 status=failed + error，不静默丢。

## 八、Prompt 设计
- 大纲 Prompt（story_prompt.py `build_outline_messages`）：输入角色/年龄/主题/时长/教育目标/家庭记忆；输出 JSON `{title, pages:[{page_no, outline}]}`（8-12 页），适龄、原创、不含具体影视 IP/在世艺术家风格。
- 正文 Prompt（`build_content_messages`）：输入已确认大纲；输出 JSON `{pages:[{page_no, text, narration, image_prompt}]}`；text 为页正文、narration 为朗读文本、image_prompt 为插画提示词（风格化、无 IP）。
- 均用 `response_format=json_object` + Pydantic 强校验 + 有限重试；数量约束（8-12 页）记为瑕疵交产品经理判断，不反复重试。

## 九、验收界面（按需）
- 需要：故事是长文本，需"用眼睛看、亲手操作"。
- 扩展 static/index.html：新增"⑥ 故事工坊"（填角色/主题 → 生成大纲 → 查看/确认 → 生成正文 → 书架列表）。

## 十、测试要求
- 第一层 mock（pytest，模型 mock）：
  1. 创建故事 → status 流转 outline_generating→outline_ready。
  2. 确认大纲 → content_generating→content_ready，pages 8-12 页。
  3. 大纲/正文解析器（宽容解析 + 校验）正反例单测。
  4. 失败路径：模型抛错 → status=failed + error。
  5. 书架列表、删除、child 不存在、参数校验。
- 第二层真实冒烟：用真实 Key 跑通 1 个完整故事（大纲→确认→正文），记录耗时与成本，交产品经理打样（D2 故事维度）。

## 十一、验收清单（产品经理照着点）
1. 打开 http://localhost:8001，选中儿童。
2. ⑥ 故事工坊：填角色名（如"小糯米"）、主题（如"刷牙"）→ 生成大纲。
3. 看到 8-12 页大纲，可改标题/页大纲 → 确认。
4. 等待正文生成，看到每页故事 + 朗读文本。
5. 书架出现这个故事，可查看、删除。

## 十二、风险与待确认项
- 插画（文生图）、朗读（TTS）需外部服务商 + Key + 费用核实 → 子阶段 3-B 单独处理（不阻塞本阶段文本核心验收）。
- 故事含儿童昵称等个人化信息，生成内容默认不用于训练（沿用 D7）。
- 必须产品经理决定：无（插画/朗读服务商将在 3-B 启动前单独确认）。
